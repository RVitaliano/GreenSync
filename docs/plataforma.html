Arquitetura do Sistema

O backend atua como a ponte entre o vaso inteligente e o aplicativo móvel. Toda a lógica de validação, persistência, regras de IA e agendamento de regas fica centralizada nesta camada, garantindo que o hardware (ESP32) foque apenas na leitura e publicação de dados.

Stack Tecnológico (Backend)

  • FastAPI: Serve a API HTTP (health check e, futuramente, endpoints /perguntar e /audio para IA) e gerencia o ciclo de vida do MQTT.
  • aiomqtt: Cliente MQTT assíncrono, responsável pela conexão com o EMQX Cloud via TLS e reconexão automática.
  • Pydantic: Realiza a validação estrita dos payloads que chegam do firmware (Modelos SensorReading e DeviceStatus).
  • Firebase Admin SDK: Gerencia as gravações no Firestore utilizando permissões de administrador.

Lógica de Persistência (Firestore)

O backend assina o tópico greensync/+/sensores. Ao receber um payload válido, ele realiza uma gravação em lote (batch write) no Firestore na coleção devices/{deviceId}:

  • leitura_atual: Sobrescrito a cada nova mensagem para garantir que o aplicativo exiba os dados em tempo real.
  • historico/{autoId}: Acumula um documento por leitura, alimentando os gráficos históricos do aplicativo.

Mensagens fora do padrão do Pydantic são logadas e descartadas de forma segura, sem interromper o serviço.

Execução e Deploy

Para desenvolvimento local, o projeto utiliza Docker e Docker Compose para subir a aplicação FastAPI (com hot-reload na porta 8000) e um broker Mosquitto para testes.

cd backend
cp .env.example .env
# Salve a chave do Firebase como backend/serviceAccountKey.json
docker compose up

Produção (Render): O deploy será feito via Render. O Dockerfile compila a imagem, e a variável $PORT dinâmica será injetada. A chave do Firebase (serviceAccountKey.json) deve ser configurada estritamente como um Secret File no painel do Render, nunca "commitada" no repositório.
