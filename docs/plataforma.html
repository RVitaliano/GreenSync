Arquitetura do Sistema

O backend atua como a ponte central entre o vaso inteligente, os serviços de IA e o aplicativo móvel. Toda a lógica de validação, persistência, orquestração de voz, agendamento de regas e gestão de OTA fica concentrada nesta camada. O Gemini nunca aciona a bomba diretamente: ele apenas interpreta o pedido e o backend aplica todas as regras de segurança.

Stack Tecnológico (Backend)

  • FastAPI + uvicorn: Processo único assíncrono (async/await) rodando em Python 3.12 no Render.
  • aiomqtt: Cliente MQTT assíncrono com reconexão automática e TLS conectado ao EMQX Serverless.
  • Pydantic: Validação estrita dos payloads MQTT (SensorReading e DeviceStatus) e configurações.
  • Firebase Admin SDK: Gravação em lote (leitura_atual + historico), agendamentos e registro de firmwares OTA no Firestore.
  • google-genai (Google Gemini): Entendimento de texto/áudio com personalidade da planta e geração de resposta falada (TTS).
  • Redis: Controle de limite de perguntas (10 por 60 s por chave) e contexto curto das últimas 3 trocas de conversa.
  • Testes Automatizados: Suíte com 973 testes em pytest cobrindo MQTT, validações, regras de rega, agendador, IA e OTA sem depender de serviços externos.

Principais Rotas da API

Endpoint Autenticação e Função
POST /perguntar X-API-Key — Perguntas em texto sobre a planta; retorna texto, estado, tela e eventual agendamento de rega.
POST /audio X-API-Key + X-Device-Id — Recebe WAV (16 kHz, 16 bits, mono, até 15 s) e devolve áudio WAV (24 kHz) com cabeçalhos X-Tela e X-Dados.
POST /dispositivos/{id}/regar X-API-Key — Aciona rega manual pelo app validando solo, status online, bomba e intervalo mínimo.
POST /dispositivos/{id}/atualizar X-API-Key — Solicita atualização OTA (wroom ou s3) a partir do registro firmware/{alvo}.
PUT /firmware/{alvo}
POST /dispositivos/{id}/reverter		 X-Admin-Key — Administração de releases OTA, rollback remoto e bloqueio de versões com falha.

Execução Local e Produção

O ambiente local utiliza Docker Compose para subir o backend (hot-reload na porta 8000), um broker Mosquitto local e o Redis:

cd backend
cp .env.example .env
# Salve a chave do Firebase em backend/serviceAccountKey.json (nunca commitar)
docker compose up

# Rodar a suíte de 973 testes automatizados
docker compose run --rm backend python -m pytest tests/ -v

Produção (Render): Deploy automático a partir da branch main com instância única, health check em /health, serviceAccountKey.json montada via Secret File (/etc/secrets/), Redis via Render Key Value e broker EMQX Serverless com TLS.
